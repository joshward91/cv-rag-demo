Harbour Help evaluation

Harbour Help answers questions about a small demo CRM using only its help centre: 29 single-task articles that match the app screen for screen. This report measures how often it finds the right article, cites it, asks when two articles are equally likely, and hands over to support when the help centre doesn't cover the question.

The assistant is designed to fail safe. When retrieval isn't confident it asks or escalates rather than answering, and an answer that can't be traced to an article it was given is withheld.

How an answer is produced

ScreenAn input guard blocks obvious prompt injection (“ignore previous instructions”, role changes, prompt extraction, tag smuggling) before anything else runs.
RewriteNormalise, apply domain phrase rules ("a client's phone" becomes a contact's phone), map synonyms, fix typos.
RetrieveField-weighted BM25 over title, aliases and body. Coverage measures how much of the question each article explains.
DecideEscalate below 55% coverage. Clarify when a look-alike scores close and covers the same terms. Otherwise answer.
GenerateOffline: the article's own steps. Claude: a schema-constrained reply that may cite only the articles in the prompt.
VerifyThe output guardrail withholds any answer that cites nothing, cites only articles it wasn't given, or contains a link. The model has no tools and no web access.

Metrics by question set

The dev set was used to tune the retriever. The test set was scored blind once, then used for a second round of tuning. The hold-out set was written before that second round and never tuned on, so it is the honest estimate for questions the system hasn't seen. The perspective set tests "client" from both sides and was scored blind once before a final one-rule fix.
